FAQ 04 · How do you use InterSystems and local data?

Real places near home, filtered by rules, ranked by Vector Search

1 · Service area

Home district, not exact address. A 15-minute walking area from OpenStreetMap routing.

2 · Candidates in FHIR

Location and HealthcareService: parks, temples, cool malls, rehab classes, walking groups.

3 · Safety filter

Rules only: intensity within the limit, open at mission time, heat and PM2.5 favour indoors.

4 · Rank

IRIS Vector Search matches the patient’s words, like “quiet, near a temple, with friends”.

5 · Three choices

Sent with the mission. The model never invents a place or a group.

InterSystems used

FHIR Server for places and services · Vector Search for ranking · FHIR SQL Builder for the filters

Honest gap

No public API lists Thai community exercise groups, so v1 uses a curated, intensity-tagged list

Data: OpenStreetMap, Thai Meteorological Department or Open-Meteo (heat), Air4Thai (PM2.5). FHIR Location near-search support on IRIS to confirm.

This is where InterSystems carries real weight. Places and services are FHIR Location and HealthcareService resources with coordinates. The rules engine filters them through FHIR SQL Builder tables. IRIS Vector Search ranks what is left against the patient’s own words. The small router model only calls these tools; it cannot make up an activity. We use the home district, not an exact address, to limit location data under PDPA.
