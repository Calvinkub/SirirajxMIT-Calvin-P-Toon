Our safety rules can also speed up decoding

1 · Draft

A small Gemma 3 model proposes the next tokens. Same family as MedGemma; tokenizer match to verify.

2 · Prune

katgpt-rs ConstraintPruner drops tokens that break the JSON schema or the allowed mission set.

3 · Tree

DDTree builds a tree of valid continuations only.

4 · Verify

MedGemma checks the tree in one pass. The output is valid by construction.

Why it fits this product

Outputs are short, structured JSON. The rule that keeps patients safe is the same rule that removes wasted tokens, so speed and safety come from one mechanism.

Benchmark before any claim

Three arms: vLLM with guided JSON, plus standard speculative decoding, plus constraint-pruned trees. Measure tokens per second, p95 latency, valid-output rate and US$ per 1,000 patient-days.

katgpt-rs is our Rust library of decoding primitives. Its published speed-ups come from micro-models, not MedGemma. No MedGemma number yet.

This is the technical wow, framed honestly. katgpt-rs implements the pipeline “LLM drafts logits, ConstraintPruner filters invalid tokens, DDTree builds a valid-only tree, target model verifies”, and a spec pruner compiles a specification into a token constraint. For us the constraint is the allowed mission set plus the JSON schema, so the target model can only ever emit a valid, allowed mission. The library itself does not load real models, so the MedGemma speed and cost numbers come from the benchmark on this slide, which we have not run yet.
